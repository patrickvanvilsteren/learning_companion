# Learning AI Agents with Microsoft Agent Framework (Python)

This guide is a beginner's learning path for building and using AI agents with the **Microsoft Agent Framework Python SDK**. It focuses on practical concepts and methods, and links to Microsoft Learn for framework-specific details.

> **Scope:** Microsoft Agent Framework is the SDK this guide focuses on. Microsoft Foundry is one model and agent-service integration described in the framework documentation; this guide is not a Foundry hosting or deployment guide. The framework also documents other model providers.
>
> The examples and exercises below are teaching suggestions, not quotations from Microsoft. For package names, provider support, and exact API syntax, use the linked documentation because those details can change.

## What you will learn

By following this guide, you will learn to:

- Explain what makes an application an agent and when a workflow is a better fit.
- Give an agent a clear task, useful context, and well-defined limits.
- Expose a small set of useful tools and keep their effects safe.
- Manage context between turns with sessions.
- Test behavior, notice failure patterns, and improve one thing at a time.

## 1. Start with the basic idea

An agent uses a model to interpret a request and produce a response. Depending on how it is built, it can also use instructions, tools, conversation state, middleware, and other context. In Python, the framework offers a common `Agent` interface across supported model providers.

An **agent** is useful when the model needs to decide what to do next, such as whether to call a tool. A **workflow** is useful when the order of steps should be explicit and controlled by your application. Start by learning one agent; add a workflow only when your task needs that control.

See Microsoft's [Agent concepts](https://learn.microsoft.com/en-us/agent-framework/concepts/agents/) and [Workflow concepts](https://learn.microsoft.com/en-us/agent-framework/concepts/workflows/).

## 2. Learn the core building blocks

| Concept | In plain language | Why it matters |
|---|---|---|
| **Model client** | The connection through which the agent sends model requests. | The provider and its capabilities affect how an agent is configured. |
| **Instructions** | Developer-provided guidance about the agent's role and behavior. | Clear instructions help keep the agent focused; they are not a substitute for application-side security checks. |
| **Tool** | A function or service the agent can ask the application to use. | Tools let an agent act or retrieve information, so their inputs and effects need controls. |
| **Session** | State used to continue a conversation across turns. | Reusing a session allows the agent to receive earlier conversation context. |
| **Middleware** | Code that can inspect or affect parts of an agent run or tool call. | It can be used for cross-cutting needs such as logging and validation. |
| **Workflow** | An explicit sequence or graph of steps, which can include code and agents. | It is useful when execution order, routing, or human input must be controlled. |

More detail: [Agent concepts](https://learn.microsoft.com/en-us/agent-framework/concepts/agents/), [Tools overview](https://learn.microsoft.com/en-us/agent-framework/agents/tools/), [Conversations and memory](https://learn.microsoft.com/en-us/agent-framework/concepts/agents/conversations/), and [Middleware](https://learn.microsoft.com/en-us/agent-framework/concepts/agents/middleware/).

## 3. Give the agent a well-defined job

Before writing code, describe the task in ordinary language. A useful task definition answers:

1. **Goal:** What should the agent accomplish?
2. **Inputs:** What information will it receive?
3. **Limits:** What must it not do or assume?
4. **Output:** What should a useful answer look like?
5. **Completion:** How will you tell whether it did the job?

For example, a small practice task could be: “Answer questions using the supplied event FAQ. If the FAQ does not contain the answer, say that you cannot find it. Reply in three short bullet points.” This is an illustrative exercise, not a special framework feature.

Keep the first task narrow. If you cannot describe what a correct result looks like, it will be difficult to tell whether a change improved the agent.

## 4. Add tools carefully

Tools are custom code or services an agent can call. Give each tool a clear purpose and enough description for the model to choose it appropriately. Begin with a small, narrow tool set; add a tool only when it enables a necessary capability.

**Important:** Tool calls and their arguments are generated by the model. Treat those arguments as untrusted input. Validate them in your application, constrain access to the minimum needed, and require human approval for high-impact actions such as modifying data or sending communications. A system instruction alone is not an authorization boundary.

Not every agent type supports every tool type. Check the provider and agent type requirements in the relevant documentation before relying on a capability.

Read [Tools overview](https://learn.microsoft.com/en-us/agent-framework/agents/tools/) and the Python examples in [Using function tools](https://learn.microsoft.com/en-us/agent-framework/agents/tools/function-tools/). For the framework's safety guidance, see [Agent Safety](https://learn.microsoft.com/en-us/agent-framework/concepts/agents/safety).

## 5. Treat conversation history as state

For a multi-turn conversation, the framework uses an `AgentSession`: create a session and pass it to subsequent runs. In Python, the documented pattern is `agent.create_session()` followed by calls to `agent.run(..., session=session)`.

Do not confuse conversation history with durable personal memory. Decide what information should be retained, where it is stored, and who is allowed to resume it. If sessions or conversation identifiers are stored by your application, associate them with the authenticated user and verify access before resuming them.

Follow [Step 3: Multi-Turn Conversations](https://learn.microsoft.com/en-us/agent-framework/get-started/multi-turn) and the [Conversations and memory overview](https://learn.microsoft.com/en-us/agent-framework/concepts/agents/conversations/).

## 6. Improve through small, repeatable tests

Use a small set of representative test requests. For each one, write down the behavior you expect before changing the agent. Include ordinary requests, unclear requests, and requests that should be refused or handled cautiously.

For each change:

1. Run the same test requests again.
2. Check both the final answer and whether the agent used its tools appropriately.
3. Investigate failures instead of adding broader instructions as a guess.
4. Change one thing at a time, then repeat the tests.

This is a practical learning routine, not a claim that the framework automatically evaluates every agent. Microsoft notes that developers remain responsible for testing and adapting applications for their use cases. See the [Agent Framework overview](https://learn.microsoft.com/en-us/agent-framework/overview/) and [Agent Safety](https://learn.microsoft.com/en-us/agent-framework/concepts/agents/safety).

## 7. Know when to use a workflow

Use an agent when the model should choose among possible next actions. Use a workflow when you want to specify the execution path—for example, a fixed sequence of steps, conditional routing, or explicit human input. Python supports graph-based workflows and also documents a functional workflow API; check the current workflow documentation for API maturity and details.

Learn with [Step 5: Workflows](https://learn.microsoft.com/en-us/agent-framework/get-started/workflows) and [Workflow concepts](https://learn.microsoft.com/en-us/agent-framework/concepts/workflows/).

## A suggested learning sequence

Work through these in order, and do not add more moving parts until the current step is understandable:

1. **Read the overview:** Learn what the framework includes and compare agents with workflows.
2. **Run a first agent:** Follow [Steps 1–2: Your First Agent and Tools](https://learn.microsoft.com/en-us/agent-framework/get-started/your-first-agent). The documented Python example uses Microsoft Foundry; follow its stated prerequisites, or choose another provider supported by the framework.
3. **Add one tool:** Start with a harmless, read-only function and observe when the agent calls it.
4. **Continue a conversation:** Reuse one session over multiple turns.
5. **Add safeguards:** Validate tool inputs and put approval in front of actions with meaningful side effects.
6. **Try a workflow:** Use one when you need an explicitly controlled sequence rather than model-selected next steps.

The [Microsoft Agent Framework documentation hub](https://learn.microsoft.com/en-us/agent-framework/) links to current tutorials, concepts, capability guides, and Python samples.

## Beginner checklist

Before calling an agent task complete, ask:

- Is the task narrow enough to explain clearly?
- Are its instructions clear about the goal, limits, and expected answer?
- Does it have only the tools it needs?
- Does application code validate tool arguments and enforce permissions?
- Do high-impact actions require approval?
- Is session state scoped to the right user?
- Have I tried normal, unclear, and unsafe or out-of-scope requests?
- Did I verify the current provider-specific requirements in Microsoft Learn?
